1. Introduction

The central objective is to assess whether a proposed computational solution is correct. A program may run without errors and still produce an inaccurate or inappropriate answer. Successful execution does not establish numerical correctness.

Uncertainty quantification uses mathematics and computation to quantify uncertainty, including uncertainty in natural phenomena. Numerical reliability is part of this broader concern: a computed result needs an explanation of its accuracy and limitations.

Motivating failures

  • Therac-25 radiation overdoses
  • Patriot missile failure
  • Ariane 5 maiden-flight failure
  • Sleipner A platform collapse

These cases involve different combinations of software, numerical, design, and validation failures. They illustrate the consequences of relying on computational results without sufficient checks.

2. AI-assisted scientific computing

AI can generate working code quickly. Evaluating the output still requires knowledge of the problem, the method, and possible numerical failure modes.

The recurring themes are stability and accuracy. Useful questions include whether an implementation solves the intended problem, how it handles invalid inputs, and whether its behavior changes under small perturbations.

Learning process

  1. Understand the problem and method; implement the method yourself when useful.
  2. Generate an AI-assisted solution.
  3. Validate the result and compare it with a reference.
  4. Explain discrepancies and what you learned.

Evaluation of AI-generated code

A useful exercise is to ask an AI assistant to implement a numerical method, then test the implementation on problems with known answers. Include inputs that may expose its assumptions, such as very small increments, large differences in scale, or invalid values.

For example, ask for a program that repeatedly adds a small number to a large one. Compare the computed sum with the exact result and examine whether each increment changes the stored value. The task is to identify a failure, explain its cause, and assess a correction. This develops the judgment needed to evaluate AI-generated scientific code.

4. Problem formulation

Well-posedness

A well-posed problem has three properties:

  1. Existence: a solution exists.
  2. Uniqueness: the solution is unique.
  3. Continuous dependence: the solution changes continuously with the input conditions, such as initial or boundary values.

These properties concern the mathematical problem itself. Describing the conditions a solution would satisfy does not establish that a solution exists.

Mathematical and computational formulations

A mathematical model and its computational implementation require separate examination. For example, an epidemic model may be expressed as differential equations, while its implementation uses a particular time-stepping method and finite-precision numbers. The resulting computation must preserve the properties needed for the intended application.

A basic linear algebra example is

Ax=b.

Formulating this equation, establishing that it has a unique solution, and choosing a reliable way to compute that solution are distinct tasks.

Conditioning and stability

Conditioning describes how sensitive a problem’s solution is to perturbations in its inputs. Continuous dependence does not imply low sensitivity. Numerical stability concerns how an algorithm handles errors introduced during computation.

Additional definition: scalar condition number

For differentiable f, with x\ne0 and f(x)\ne0, the local relative condition number is

\kappa_f(x)=\left|\frac{x f'(x)}{f(x)}\right|.

For example, f(x)=x-1 is continuous, but \kappa_f(x)=|x/(x-1)| becomes large near 1. Small relative changes in the input can produce much larger relative changes in the output. See the Cornell numerical analysis notes.

5. Number representation

Scientific notation

Floating-point representation uses a significand and an exponent, as in scientific notation:

123456=1.23456\times10^5,
0.00568=5.68\times10^{-3}.

The sign of the number and the sign of the exponent have different roles. A negative exponent changes the scale; it does not make a positive number negative.

Positional notation

Each digit contributes its value multiplied by a power of the base. For example, the binary number (101.01)_2 represents

\begin{aligned}5.25&=1\cdot2^2+0\cdot2^1+1\cdot2^0\\&\quad+0\cdot2^{-1}+1\cdot2^{-2}.\end{aligned}

Its normalized form is (1.0101)_2\times2^2, which requires five significant binary digits.

Normalized floating-point representation

x=s\,(d_0.d_1\ldots d_{p-1})_\beta\,\beta^e.
SymbolMeaning
\betaBase, such as 2 or 10
pNumber of significant digits, including the leading digit
L,ULower and upper exponent bounds
eInteger exponent satisfying L\le e\le U
sSign, either -1 or +1
d_iDigits in \{0,1,\ldots,\beta-1\}

For a normalized nonzero number, d_0\ne0. In binary, the leading digit must therefore be 1. Zero is represented separately.

6. Floating-point systems

Example system

Let’s consider a system with the following parameters:

\beta=2,\qquad p=3,\qquad L=-1,\qquad U=2.

A significand has three binary digits:

(1.d_1d_2)_2=1+\frac{d_1}{2}+\frac{d_2}{4}.

The four possibilities are (1.00)_2=1, (1.01)_2=1.25, (1.10)_2=1.5, and (1.11)_2=1.75. Multiplying them by each allowed power of two gives the positive representable values.

Range and spacing

For a normalized system, the smallest and largest positive values are

x_{\min}^{+}=\beta^L,
x_{\max}=(\beta-\beta^{1-p})\,\beta^U.

Within an exponent block, the spacing is

\Delta_e=\beta^{e-p+1}.

For the three-digit binary example, x_{\min}^{+}=0.5, x_{\max}=7, and \Delta_e=2^{e-2}. Increasing the exponent by one doubles the spacing. Increasing the precision by one halves the spacing at a fixed exponent.

Range and exact representability are different. The number 4.625 lies within the system’s range but between its available values. The number 8 requires exponent 3 and is outside the range.

Additional example: rational numbers in binary

A reduced rational number has a terminating binary expansion only if its denominator is a power of 2. Thus 1/8=(0.001)_2 terminates, while 1/10=(0.000110011\ldots)_2 repeats. A terminating expansion must also fit the system’s precision and exponent bounds to be stored exactly.

7. Numerical errors

Representation error

An input may need to be replaced with an available machine number before arithmetic begins. Let \operatorname{fl}(x) denote the rounded representation of x.

In the three-digit binary example, the smallest positive value is 0.5. Under rounding to the nearest available number,

\operatorname{fl}(0.1)=0.

This example concerns the gap near zero. Even a binary system with a much wider exponent range still cannot represent 0.1 exactly with finitely many digits, because its binary expansion repeats.

Arithmetic rounding error

Exactly representable inputs can produce a result that is not representable. Both 4 and 0.625 are available, but

4+0.625=4.625.

Rounding the result to the nearest available value gives

\operatorname{fl}(4+0.625)=5,\qquad 5-4.625=0.375.

The inputs introduced no representation error. The error entered when the arithmetic result was rounded.

StageSource of error
Input representationThe original value is not available in the number system.
Arithmetic operationThe exact result is not available in the number system.

Small increments and operation order

Using the example’s midpoint rule, 4.5 rounds to 4. Adding a nonzero increment can therefore leave the stored value unchanged:

\operatorname{fl}(4+0.5)=4.

As a worked consequence, the order of addition matters:

\operatorname{fl}\bigl(\operatorname{fl}(4+0.5)+0.5\bigr)=4,
\operatorname{fl}\bigl(4+\operatorname{fl}(0.5+0.5)\bigr)=5.

The first computation loses the two increments separately. The second combines them into 1 before adding them to 4. Floating-point addition is not generally associative.

Error propagation and validation

Individual errors may be small but can be amplified or accumulated during a computation. A larger numerical range alone does not remove the finite set of representable values.

A practical starting point is a simple problem with a known answer. Compute the result, compare it with the reference, and identify where any discrepancy entered.

  • Check whether the mathematical problem is well posed.
  • State the assumptions introduced by the computational method.
  • Separate input representation errors from arithmetic errors.
  • Compare with an analytic answer or an independent calculation.
  • Explain the effects of precision, input scale, and operation order.
