1. Review of Class 2

Floating-point arithmetic

A floating-point number system contains a finite set of representable values. It is not dense in the real numbers, unlike the rational numbers: rational approximations can be made arbitrarily close to any real number, whereas a fixed floating-point system has gaps.

Two limitations must be kept separate: the range of finite representable magnitudes and the precision available within that range. Rounding also means that familiar algebraic properties need not carry over to the implemented operations. For example,

\operatorname{fl}\!\left(\operatorname{fl}(a+b)+c\right) \ne \operatorname{fl}\!\left(a+\operatorname{fl}(b+c)\right)

can occur even though the two expressions are equal in exact arithmetic. Cancellation can remove significant information, and a small increment can disappear when added to a much larger number.

The quadratic formula and the summation examples in Class 2 show why algebraically equivalent procedures can give different numerical results. The same issue appears when solving linear systems.

Harmonic series

If an infinite series converges, its terms must tend to zero. The converse is false. The harmonic series is the basic counterexample:

H_N=\sum_{i=1}^{N}\frac{1}{i}, \qquad \frac{1}{i}\longrightarrow 0, \qquad H_N\longrightarrow\infty.

The integral comparison explains the divergence:

H_N\ge \int_{1}^{N+1}\frac{dt}{t} =\ln(N+1)\longrightarrow\infty.

Finite-precision failures

FailureWhat happens?
Loss of a small incrementThe next term is nonzero, but adding it to a much larger partial sum does not change the stored sum.
UnderflowThe term becomes too small to be represented and is rounded to zero.
OverflowThe accumulated sum exceeds the finite representable range.

The computational question is which failure happens first, and how many steps it takes. The harmonic series grows very slowly, even though it diverges mathematically.

A stored sum that stops changing does not prove mathematical convergence. The direct and chunked summations in Class 2 provide another way to investigate the role of operation order.

2. Gaussian elimination and pivoting

Linear algebra is a central computational tool, including for approximations to nonlinear problems. The basic task is to find x in

Ax=b.

Gaussian elimination removes a variable by subtracting a multiple of one equation from another. Eliminate the first variable, then substitute back to obtain the other variable. The coefficient used for this elimination step is the pivot.

Small pivot

A=\begin{bmatrix}0.0001&1\\1&1\end{bmatrix}, \qquad b=\begin{bmatrix}1\\2\end{bmatrix}, \qquad \begin{cases} 0.0001x_1+x_2=1,\\ x_1+x_2=2. \end{cases}

First keep the equation order fixed. Eliminating x_1 from the second equation requires the multiplier

\frac{1}{0.0001}=10000.

Multiply the first equation by 10000, then subtract it from the second equation. Apply the subtraction to both sides:

\begin{aligned} x_1+x_2&=2,\\ -(x_1+10000x_2)&=-10000,\\ \hline -9999x_2&=-9998. \end{aligned}

The exact triangular system is therefore

\begin{bmatrix}0.0001&1\\0&-9999\end{bmatrix} \begin{bmatrix}x_1\\x_2\end{bmatrix} =\begin{bmatrix}1\\-9998\end{bmatrix}.

Substituting back gives

x_2=\frac{9998}{9999}=0.999899989998\ldots, \qquad x_1=\frac{1-x_2}{0.0001} =\frac{10000}{9999}=1.000100010001\ldots.

Three-digit arithmetic

Now use a base-10 system with p=3 significant digits, rounding after each arithmetic operation. Assume the exponent range is wide enough for all intermediate values. All entries of the original system can be represented exactly in this toy system, including 0.0001=1.00\times10^{-4}.

\operatorname{fl}(-9999)=-1.00\times10^4, \qquad \operatorname{fl}(-9998)=-1.00\times10^4.

The distinction between these two numbers disappears, giving

x_2=\frac{-10000}{-10000}=1, \qquad x_1=\frac{1-1}{0.0001}=0.

Rounding x_2 to 1 looks harmless by itself. But the first equation recovers x_1 from the small difference 1-x_2, then divides by 0.0001. Losing that difference produces a 100\% relative error in x_1.

Row interchange

Interchanging the two equations leaves the exact problem unchanged:

\begin{cases} x_1+x_2=2,\\ 0.0001x_1+x_2=1. \end{cases}

The first pivot is now 1. Multiply the first equation by 0.0001, then subtract it from the second equation:

\begin{aligned} 0.0001x_1+x_2&=1,\\ -(0.0001x_1+0.0001x_2)&=-0.0002,\\ \hline 0.9999x_2&=0.9998. \end{aligned}

In three-significant-digit arithmetic, the last equation becomes 1.00x_2=1.00. Back substitution now uses the equation x_1+x_2=2, so

x_2=1,\qquad x_1=2-1=1.

The approximate solution (1,1)^T is close to the exact solution. The same mathematical system gives a very different computed answer solely because the row order changed. This row-reordering step is an example of pivoting.

3. Condition number

Changing an algorithm is not the only way to change an answer. A problem can itself be highly sensitive to small changes in its input, even when the calculation is exact.

Sensitivity of the tangent function

Consider the function evaluation x=\tan(b), with angles measured in radians:

b=1.57079,\qquad b^*=1.57078,\qquad \delta b=|b-b^*|=10^{-5}.

Both inputs lie just below and very close to the tangent function’s vertical asymptote at

\frac{\pi}{2}\approx 1.5707963268.

The curve is steep near this value, so the small input difference produces a much larger output difference:

\begin{aligned} x=\tan(b)&\approx 158057.9134185,\\ x^*=\tan(b^*)&\approx 61249.0085313,\\ \delta x=|x-x^*|&\approx 96808.9048873. \end{aligned}

For these inputs, the condition number measures the amplification of the input change:

\underbrace{\frac{\delta x}{\delta b}}_{\text{condition number}}=\frac{|x-x^*|}{|b-b^*|}
\frac{\delta x}{\delta b}\approx 9.68\times10^9\approx 10^{10}.

A large condition number means that small input changes are strongly amplified.

A change of only 10^{-5} in the input produces a change of almost 10^5 in the output.

Well-posedness and conditioning

A well-posed problem has a solution, has a unique solution, and depends continuously on its input. On the open interval (-\pi/2,\pi/2), tangent is continuous. However, in this case it is ill-conditioned, because the inputs are close to the asymptote at \pi/2 and small input changes are strongly amplified.

Continuity does not impose a small amplification factor. It is therefore possible for a problem to be mathematically well-posed at a given input and still be numerically sensitive there.

Representation error connects this issue to floating-point arithmetic. If the intended input b is unavailable and the computer substitutes a nearby representable value b^*, even a perfectly accurate evaluation of \tan(b^*) may be far from the desired \tan(b).

4. Ill-conditioned linear system

The same sensitivity can occur in a linear solve. Now consider a different matrix from the small-pivot example:

A=\begin{bmatrix}1&1\\1&1.0001\end{bmatrix}.

Keep A fixed and regard the right-hand side b as the input. The output is the solution x.

First case

\begin{bmatrix}1&1\\1&1.0001\end{bmatrix} \begin{bmatrix}x_1\\x_2\end{bmatrix} =\begin{bmatrix}2\\2\end{bmatrix}.

Subtracting the first row from the second gives

\begin{bmatrix}1&1\\0&0.0001\end{bmatrix} \begin{bmatrix}x_1\\x_2\end{bmatrix} =\begin{bmatrix}2\\0\end{bmatrix}, \qquad x=\begin{bmatrix}2\\0\end{bmatrix}.

Second case

Change only the second component of b, from 2 to 2.0001:

\begin{bmatrix}1&1\\1&1.0001\end{bmatrix} \begin{bmatrix}x_1^*\\x_2^*\end{bmatrix} =\begin{bmatrix}2\\2.0001\end{bmatrix}.

The same elimination now gives

\begin{bmatrix}1&1\\0&0.0001\end{bmatrix} \begin{bmatrix}x_1^*\\x_2^*\end{bmatrix} =\begin{bmatrix}2\\0.0001\end{bmatrix}, \qquad x^*=\begin{bmatrix}1\\1\end{bmatrix}.

The input perturbation and the change in the solution are

b^*-b=\begin{bmatrix}0\\0.0001\end{bmatrix}, \qquad x^*-x=\begin{bmatrix}-1\\1\end{bmatrix}.

These are different exact solutions of two nearby problems. No rounding error is needed to produce the large change. Pivoting cannot remove sensitivity that belongs to the input-output relationship itself.

Near linear dependence

The columns (1,1)^T and (1,1.0001)^T are linearly independent, but close to being identical. The rows are also nearly dependent. The matrix is invertible, yet it is close to a singular matrix.

In the tangent example, proximity to an asymptote creates large sensitivity. Here, the analogous structural issue is proximity to linear dependence.

5. Equivalent conditions for invertibility

Let A\in\mathbb{R}^{n\times n}. The following statements are equivalent in exact mathematics:

  1. A^{-1} exists.
  2. There is no nonzero vector x such that Ax=0.
  3. The columns of A are linearly independent.
  4. The rows of A are linearly independent.
  5. \det(A)\ne0.
  6. For every right-hand side b\in\mathbb{R}^n, there is exactly one vector x satisfying Ax=b.

These statements answer an existence-and-uniqueness question. They do not say that the solution is insensitive to perturbations. For the nearly dependent example,

\det\begin{bmatrix}1&1\\1&1.0001\end{bmatrix}=0.0001\ne0,

yet the two nearby right-hand sides have markedly different solutions.

These are equivalent statements in exact mathematics. Finite-precision calculations used to check them need not agree. Existence and uniqueness alone do not establish that the numerical solution is reliable.

6. Sources of numerical error

Numerical reliability can be lost in three ways:

SourceWhat changes?Example
Representation errorThe intended input is replaced by an available floating-point value.Using a nearby b^* instead of b.
Rounding and cancellation during an algorithmIntermediate operations lose information, sometimes in an order-dependent way.The small-pivot solve returns (0,1)^T at p=3; row interchange returns (1,1)^T.
Ill-conditioning of the problemA small change in the input produces a large change in the exact output.Tangent near \pi/2, or the nearly dependent matrix with perturbed b.

Algorithmic stability and problem conditioning are different questions. The first asks how a computational procedure handles numerical errors; the second asks how sensitive the mathematical answer is to the data. Representation error can supply the perturbation, and an ill-conditioned problem can then amplify it.

The practical contrast is:

\begin{array}{ll} \text{Small-pivot example:}&\text{same problem, different operation order},\\ \text{Nearly dependent example:}&\text{nearby inputs, different exact solutions}. \end{array}

More appropriate operation ordering can improve the first case. It cannot make the two exact solutions in the second case equal. Likewise, a program finishing without an exception does not establish that its numerical result is trustworthy.
